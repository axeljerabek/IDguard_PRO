## 1. CORE SYSTEM PATHS (AUTO-MANAGED)
All paths are resolved relative to the project root. You do not need to set these manually unless you want to override the default directory structure.

*   **`PROJECT_ROOT`**: The absolute path of your installation folder.
*   **`ALERTS_DIR`**: Destination for all `.mp4` event files. 
    - *Location*: `{PROJECT_ROOT}/alerts/`
*   **`LOG_DIR`**: Storage for both system logs and per-camera logs.
    - *Location*: `{PROJECT_ROOT}/logs/`
*   **`MODEL_PATH`**: The absolute path to your YOLOv10 weights (`.pt`).

---

## 2. STREAM CONFIGURATION (`STREAMS`)
The `STREAMS` list defines the active cameras. Each entry is a dictionary:

| Key | Type | Description |
| :--- | :--- | :--- |
| **`name`** | `string` | Unique ID (used in logs, filenames, and alerts). |
*   **`url`** 	| `string` | The RTMP/RTSP stream origin URL. |
*   **`enabled`**| `boolean`| Set to `True` to activate; `False` to ignore the camera entirely. |
*   **`type`** 	| `string` | Currently supports `"VIDEO"`. |

**Example Configuration:**
```python
STREAMS = [
    {"name": "Entrance_Main", "url": "rtmp://192.168.178.25/pi/test", "enabled": True, "type": "VIDEO"},
    {"name": "Garden_North",  "url": "rtmp://192.168.178.25/garden/live", "enabled": False, "type": "VIDEO"}
]
```

## 3. DETECTION & AI PARAMETERS
Controls the Intelligence and sensitivity of the detection engine.

*   **`DETECTION_CLASSES`**: **[CRITICAL]** A list of integer IDs representing the objects you want to track (based on COCO/YOLO classes).
    - `0`: Person (Default)
    - `1`: Bicycle
    - `2`: Car
    - *Example*: `[0, 2]` will trigger alerts for both humans and vehicles.
*   **`CONFIDENCE_THRESHOLD`**: A float (`0.0` to `1.0`). Determines how certain the AI must be before it triggers an alert (e.g., `0.5`).

---

## 4. TEMPORAL & RECORDING LOGIC
Controls buffer management and video duration per event.

*   **`PRE_ROLL_SEC`**: Seconds of "pre-event" footage kept in the circular RAM buffer. When an event triggers, this historical data is written to the *start* of your `.mp4` file.
    - *Warning*: High values increase RAM consumption!
*   **`POST_ROLL_SEC`**: Seconds to continue recording **after** the target object has left the frame. Ensures you capture the "exit" phase.
*   **`TARGET_FPS`**: The target frames per second for the output video (e.g., `30`).

---

## 5. OPERATIONAL MODES
Currently implemented:

*   **`RECORDING_MODE = "EVENT_DRIVEN"`**
    - **Workflow**: `IDLE` $\rightarrow$ *Detection Found* $\rightarrow$ `RECORDING` (Pre-roll + Event + Post-roll) $\rightarrow$ `IDLE`.
    - This mode is highly efficient as it only consumes disk/CPU when active motion is detected.

---

## 6. MULTI-LEVEL LOGGING
The system provides two distinct logging streams:

1.  **`system_logger` (SYSTEM)**: Monitors the orchestrator, thread lifecycle, and global errors. Saved in `logs/system_main.log`.
2.  **`stream_logger` ({name})**: Detailed per-camera logs containing connection errors, detection timestamps, and frame drops. Saved as `logs/{camera_name}.log`.
